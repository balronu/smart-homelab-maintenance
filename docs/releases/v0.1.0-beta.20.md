# v0.1.0-beta.20 – Updateverwaltung ohne Ausführung (Kandidat)

## Deutsch

- Passive Update-Erkennung liest vorhandene APT-Cache-Daten über den festen
  Aufruf `apt list --upgradable`; keine Paketlistenaktualisierung oder
  Installation wird ausgelöst.
- Updateprüfungen, Dry Runs und die dauerhaft gesperrte echte Ausführung sind
  technisch getrennt. Der Dry Run bleibt an eine frische, unveränderte
  Prüfung und eine verpflichtende Serviceantwort gebunden.
- Gastziele sind standardmäßig nicht autorisiert. Nur eine ausdrücklich
  konfigurierte Allowlist kann laufende Debian-/Ubuntu-LXCs freigeben;
  gestoppte Container werden nicht gestartet. VMs ohne Gastzugriff bleiben
  `not_checked`.
- Die Karte zeigt Paketnamen und Versionswechsel, soweit vorhanden, sowie
  eindeutige Statuswerte. Sicherheitszahlen werden nicht erfunden.
- „Updates installieren“ ist sichtbar, deaktiviert und ohne Serviceaufruf;
  die Server-API enthält weiterhin keinen Ausführungspfad.

Dies ist ein Kandidat und kein veröffentlichtes Release. Beta.19-Tag und
produktive Systeme bleiben unverändert. Vor einer späteren Veröffentlichung
sind CI, HACS, HA-Runtime und die Agent-Kompatibilität erneut zu prüfen.

## English

- Passive update detection reads existing APT cache data with the fixed
  `apt list --upgradable` command; it never refreshes indexes or installs.
- Detection, dry runs, and real execution remain technically separate. Dry runs
  require a fresh unchanged check and a mandatory service response.
- Guest targets are unauthorized by default. Only an explicit allowlist can
  authorize running Debian/Ubuntu LXCs; stopped containers are never started.
  VMs without guest access remain `not_checked`.
- The card displays package names and version changes where available and does
  not invent security classifications.
- “Install updates” is visible, disabled, and has no service call; server-side
  execution remains unavailable.

This is a candidate, not a published release. The Beta.19 tag and productive
systems remain unchanged. CI, HACS, HA runtime, and agent compatibility must
be rechecked before publication.
