# v0.1.0-beta.25 – Agent lifecycle and port bind safety

## Deutsch

Beta.25 enthält den Lifecycle- und Updater-Fix für den wiederkehrenden
`[Errno 98] Address already in use`-Fehler beim kontrollierten Agent-Upgrade.
Der Agent behandelt `SIGTERM` und `SIGINT` kontrolliert, beendet die
Server-Schleife und schließt den HTTPS-Listen-Socket. Der Updater prüft Port
48128 nach dem Dienststopp und vor dem atomaren Austausch. Ein belegter Port
führt zu einem sicheren Abbruch; eine zweite Agent-Instanz wird nicht gestartet.

Der Beta.24-Fix für den kanonischen Dry-Run-Planvergleich ist enthalten:
unterschiedliche Paket-Reihenfolge führt nicht mehr zu einem falschen Stale-
Abbruch, echte Paket- oder Versionsabweichungen bleiben ein Sicherheitsabbruch.
Der Installationsbutton bleibt dauerhaft deaktiviert; echte Paketupdates,
Helper, Socket und Allowlist bleiben gesperrt.

Integration und Agent verwenden `0.1.0-beta.25`, der API-Vertrag bleibt `1.1`.
Die separat laufende Agent-Installation wird durch HACS nicht automatisch
aktualisiert. Für einen produktiven Agent-Upgradeversuch ist ein eigener,
kontrollierter Auftrag mit Preflight und Readiness-Healthcheck erforderlich.

## English

Beta.25 fixes the recurring `[Errno 98] Address already in use` failure during
controlled agent upgrades. The agent handles `SIGTERM` and `SIGINT` explicitly,
exits its server loop, and closes the HTTPS listening socket. The updater
verifies that port 48128 is free after stopping the service and before the
atomic swap. A busy port causes a safe abort; a second agent instance is never
started.

The Beta.24 canonical dry-run plan comparison remains included: ordering-only
differences no longer cause a false stale-plan rejection, while real package or
version differences remain a safety abort. The install button stays permanently
disabled; real package updates, the helper, socket, and allowlist remain locked.

Integration and agent use `0.1.0-beta.25`; the API contract remains `1.1`.
HACS does not automatically update the separately deployed agent. A productive
agent upgrade requires its own controlled request with preflight and readiness
health verification.

## Compatibility and limitations

- GitHub prerelease; stable remains unchanged.
- No Home Assistant installation or restart is included.
- No productive agent upgrade, dry run, package update, firewall change,
  backup, snapshot, helper, socket, or allowlist activation is included.
- Historical and failed rollback staging must be preserved and checked before
  any later productive upgrade.
