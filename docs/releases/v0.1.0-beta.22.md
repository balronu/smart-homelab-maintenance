# v0.1.0-beta.22 – sicherer Agent-Preflight

## Deutsch

- Der Agent-Updater erkennt vorhandenes Rollback-Staging nur dann als
  historisch, wenn Version, aktiver Dienst und TLS-validierter Healthcheck
  zusammenpassen.
- Historische Staging-Verzeichnisse werden nicht gelöscht, umbenannt oder
  überschrieben. Ungültige, gleich alte, neuere oder mehrdeutige Stände
  blockieren den Preflight weiterhin.
- Beim späteren kontrollierten Austausch wird der passende Rollback-Stand
  anhand der zuvor aktiven Agent-Version gewählt.
- API-Vertrag 1.1 bleibt unverändert. Der Root-Helper und die LXC-Allowlist
  bleiben standardmäßig deaktiviert; echte Paketupdates bleiben gesperrt.

Beta.22 ist ein GitHub-Prerelease. Der Agent läuft nicht automatisch durch ein
HACS-Update mit; produktive Agent-Installation und HA-Aktualisierung bleiben
separate, ausdrücklich freizugebende Schritte.

## English

- The agent updater recognizes existing rollback staging as historical only
  when the version, active service, and TLS-validated healthcheck agree.
- Historical staging directories are never deleted, renamed, or overwritten.
  Invalid, equal/newer, or ambiguous staging continues to block preflight.
- During a later controlled exchange, the matching rollback state is selected
  by the previously active agent version.
- API contract 1.1 remains unchanged. The root helper and LXC allowlist stay
  disabled by default; real package updates remain blocked.

Beta.22 is a GitHub prerelease. HACS does not update the separate agent
automatically; productive agent installation and HA updates remain separate,
explicitly approved steps.
