# v0.1.0-beta.26 – Forensic port gate and upgrade-race protection

## Deutsch

Beta.26 erweitert den Beta.25-Lifecycle-Fix für den wiederkehrenden
`[Errno 98] Address already in use`-Fehler. Der Updater prüft Port 48128 über
alle TCP-Zustände und die tatsächliche systemd-Inaktivität. `LISTEN` und aktive
Zustände bleiben blockierend; ausschließlich der terminale, kernelverwaltete
`TIME-WAIT`-Zustand wird bei `SO_REUSEADDR` ausgenommen. Eine zweite Prüfung
unmittelbar vor `systemctl start` schließt das Stop-/Swap-/Start-Rennen.

Die Port-Diagnose protokolliert ausschließlich nicht-sensitive MainPID-,
ControlPID-, Cgroup- und Socketdaten. Historische und fehlgeschlagene
Rollback-Stagings bleiben erhalten. Der Beta.24-Fix für den kanonischen
Dry-Run-Planvergleich ist enthalten: reine Paket-Reihenfolgeunterschiede
führen nicht zum falschen Stale-Abbruch, echte Paket- oder Versionsabweichungen
bleiben ein Sicherheitsabbruch.

Integration und Agent verwenden `0.1.0-beta.26`; der API-Vertrag bleibt `1.1`.
Der Installationsbutton bleibt dauerhaft deaktiviert. HACS aktualisiert den
separat laufenden Agenten nicht automatisch. Kein Home-Assistant-Neustart und
keine produktive Installation sind Teil dieses Releases.

## English

Beta.26 extends the Beta.25 lifecycle fix for the recurring
`[Errno 98] Address already in use` failure. The updater checks all TCP states
on port 48128 and confirms actual systemd inactivity. `LISTEN` and active
states remain blocking; only terminal kernel-owned `TIME-WAIT` is exempted for
the `SO_REUSEADDR` bind. A second check immediately before `systemctl start`
closes the stop/swap/start race.

Port diagnostics record only non-sensitive MainPID, ControlPID, cgroup, and
socket data. Historical and failed rollback staging is preserved. The Beta.24
canonical dry-run plan comparison remains included: ordering-only package
differences do not cause a false stale rejection, while real package or
version differences remain a safety abort.

Integration and agent use `0.1.0-beta.26`; the API contract remains `1.1`.
The install button stays permanently disabled. HACS does not automatically
update the separately deployed agent. No Home Assistant restart or productive
installation is included in this release.

## Compatibility and limitations

- GitHub prerelease; stable remains unchanged.
- No productive agent or Home Assistant installation, restart, dry run,
  package update, firewall change, backup, snapshot, helper, socket, or
  allowlist activation is included.
- A later productive agent upgrade requires a separate explicit authorization,
  preflight, TLS/API readiness check, and rollback verification.
