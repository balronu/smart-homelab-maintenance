# Smart Homelab Maintenance v0.1.0-beta.43 candidate

## Deutsch

Beta.43 ist der gezielte systemd-Policy-Write-Fix für Issue #63. Der Helper
behält `ProtectSystem=strict`; nur das root-owned Policy-Verzeichnis wird als
Schreibpfad freigegeben. Der atomare Write nutzt eine temporäre Datei im selben
Dateisystem, `os.replace()`, Datei-/Verzeichnissynchronisation und Fail-Closed-
Validierung. Bestehende Grants werden bei der Installer-Migration erhalten.

Die systemd-Akzeptanzprüfung führt `policy_set`, Read-back, Widerruf und
erneuten Read-back über den echten Helper-Socket unter der Sandbox aus. Es
werden keine LXC-Kommandos, Paketaktionen oder produktive Berechtigungen
ausgeführt. Beta.42, HA, Agent, Helper und CT110 bleiben bis zu einer neuen
separaten Freigabe unverändert.

Der HA-Orchestrierungsstatus wird pro Anfrage gelesen, damit der Sensor nicht
wegen eines Startreihenfolge-Snapshots auf `unavailable` hängen bleibt.

## English

Beta.43 is the targeted systemd policy-write fix for Issue #63. The helper
retains `ProtectSystem=strict`; only the root-owned policy directory is made
writable. Atomic writes use a same-filesystem temporary file, `os.replace()`,
file/directory synchronization and fail-closed validation. Existing grants are
preserved during installer migration.

The systemd acceptance test performs `policy_set`, read-back, revoke and a
second read-back through the real helper socket under the sandbox. It performs
no LXC command, package action or productive permission change. Beta.42, HA,
agent, helper and CT110 remain unchanged pending separate approval.

The HA orchestration status is read per request so a startup-order snapshot
cannot leave the sensor stuck at `unavailable`.

Merge, publication and productive installation require separate approval.
