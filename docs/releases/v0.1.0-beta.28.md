# v0.1.0-beta.28 – APT architecture parsing and stale-state lifecycle

## Deutsch

Beta.28 korrigiert den APT-Parser für die reguläre Architekturspalte in
`apt list --upgradable`. Zeilen mit `amd64` oder `all` behalten jetzt die
installierte Version. Der kanonische Digest akzeptiert weiterhin identische
Paketpläne unabhängig von der Reihenfolge und blockiert echte Paket- oder
Versionsabweichungen weiterhin sicher.

Der HA-Coordinator hält das letzte Dry-Run-Ergebnis getrennt von den aktuellen
Update-Metadaten im Arbeitsspeicher. Ein alter stale-Status kann daher neben
einem frischen Updatecheck bestehen bleiben, bis eine neue Dry-Run-Antwort den
Ergebnisstand ersetzt. Beta.28 löscht oder manipuliert gespeicherte Zustände
nicht automatisch; es wurde kein produktiver Dry Run ausgeführt.

Integration und Agent verwenden `0.1.0-beta.28`; der API-Vertrag bleibt `1.1`.
Der Installationsbutton bleibt dauerhaft deaktiviert. Der Parser-Fix ändert
nicht die Autorisierungs-, Rollback- oder Sicherheitsprüfungen.

## English

Beta.28 fixes APT parsing for the regular architecture column in
`apt list --upgradable`. Lines containing `amd64` or `all` now retain the
installed version. The canonical digest continues to accept identical package
plans independent of ordering and safely blocks real package or version
changes.

The HA coordinator keeps the last dry-run result separate from current update
metadata in memory. An old stale result can therefore coexist with a fresh
update check until a new dry-run response replaces the result state. Beta.28
does not automatically delete or mutate stored state; no productive dry run
was executed.

Integration and agent use `0.1.0-beta.28`; the API contract remains `1.1`.
The install button remains permanently disabled. The parser fix does not
change authorization, rollback, or security checks.

## Compatibility and limitations

- GitHub prerelease; stable remains unchanged.
- The coordinator stale-result lifecycle is documented, not reset or changed
  by this release.
- No productive agent or Home Assistant installation, restart, dry run,
  package update, firewall change, backup, snapshot, helper, socket, or
  allowlist activation is included.
- A later productive upgrade requires separate explicit authorization and
  preflight verification.
