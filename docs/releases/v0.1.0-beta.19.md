# v0.1.0-beta.19 – Dry Runs und passive Update-Erkennung

## Deutsch

- Behebt den Lovelace-Serviceaufruf für `smart_homelab_maintenance.dry_run`:
  die verpflichtende Home-Assistant-Serviceantwort wird angefordert und
  Ergebnisse, Paketänderungen, Warnungen, Fehler und Zeitüberschreitungen werden
  sichtbar dargestellt.
- Die passive Update-Erkennung unterscheidet `updates_available`, `current`,
  `not_checked`, `unsupported`, `unauthorized`, `error`, `stale` und `unknown`.
  Unbekannt wird nicht als aktuell oder als „keine Updates“ interpretiert.
- Proxmox-Inventar allein beweist kein Gastbetriebssystem und keinen
  Paketmanager. LXCs bleiben deshalb ohne ausdrücklich geprüfte Gastmetadaten
  `unsupported`; VMs ohne autorisierten Gastzugriff bleiben `not_checked`.
- Die optionale Allowlist akzeptiert nur feste Ziel-IDs sowie OS-, Versions- und
  Paketmanager-Metadaten. Sie akzeptiert keine Shell-Befehle, Pfade oder
  Credentials und wird nicht automatisch aktiviert.
- Echte Updates, Paketlistenaktualisierungen, Installationen, Neustarts und
  automatische Freigaben bleiben serverseitig deaktiviert.

Beta.19 ist ein GitHub-Prerelease. HACS aktualisiert nur Integration und Karte;
der separat laufende Agent wird nicht automatisch aktualisiert. Eine spätere
Agent-Aktualisierung benötigt einen eigenen Preflight, Integritätsprüfung,
ausdrückliche Freigabe und Healthcheck. Der produktive Agent und die Gäste
wurden für dieses Release nicht verändert.

## English

- Fixes the Lovelace call to `smart_homelab_maintenance.dry_run` by requesting
  the mandatory Home Assistant service response and displaying results, package
  changes, warnings, errors, and timeouts.
- Passive update detection distinguishes `updates_available`, `current`,
  `not_checked`, `unsupported`, `unauthorized`, `error`, `stale`, and `unknown`.
  Unknown is never treated as current or as no updates.
- Proxmox inventory alone does not prove a guest operating system or package
  manager. LXCs therefore remain `unsupported` without explicitly verified guest
  metadata; VMs without authorized guest access remain `not_checked`.
- The optional allowlist accepts only fixed target IDs and OS, version, and
  package-manager metadata. It accepts no shell commands, paths, or credentials
  and is not activated automatically.
- Real updates, package-index refreshes, installations, restarts, and automatic
  approvals remain server-side disabled.

Beta.19 is published as a GitHub prerelease. HACS updates the integration and
card only; it does not automatically update the separately running agent. Any
later agent update requires its own preflight, integrity check, explicit
approval, and health check. No productive agent or guest system was changed for
this release.
